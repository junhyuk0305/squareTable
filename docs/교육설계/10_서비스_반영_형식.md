# 10. 서비스 반영 형식

모든 분기가 최종적으로 데이터·확인 경로·상태·코스·화면·측정으로 어떻게 들어가는지를 한 표로 모은다. 구현 명세의 전 단계다. 새 화면은 없다. 노하우에 꼬리표 하나, 노하우 유형 하나, 확인 경로 하나, 상태 한 칸이 들어간다. 판정은 전부 코드가 하고 사장은 고르지 않는다.

## 1. 한 줄 요약

**노하우에 "알기·하기·겪기" 꼬리표가 붙고, 꼬리표가 확인 경로를 고르고, 세 경로의 결과가 네 칸짜리 상태 하나로 모인다.** 사장이 배워야 할 개념은 그 네 단어(보여줬다·같이 했다·시켜봤다·맡겼다)뿐이다.

## 2. 형식 표

| 층 | 무엇 | 형식 | 판정 규칙 | 지금 | 분기 |
| --- | --- | --- | --- | --- | --- |
| 데이터 | 노하우의 묶음 꼬리표 | `learn` = 알기 · 하기 · 겪기 (복수 가능) | 코드가 구조에서 판정: 값·이름·자리 → 알기 / 순서 3단계 이상·금지 → 하기 / 상황 갈래·주관 기준(spectrum) → 겪기. 사장은 뒤집기만 | `detect.ts` 확장 | A·E |
| 데이터 | 자리 지도 노하우 | 사진 1장 + 핀 N개(좌표·이름). 음성으로 이름 입력 | 핀 5개 이상이면 묶음. 코스 카드가 5개씩 쪼개 발송 | 새 유형 | C |
| 데이터 | 직원×업무 상태 | 모름 · 봤어요 · 같이 했어요 · 혼자 했어요 · 맡았어요 | `knowhow_understanding`(알기) + 할일 완료·`task_understanding`(하기) + 사장/선배 확인(겪기)에서 파생. 저장 안 하고 계산 | 기존 3표 조합 | E |
| 데이터 | 사수 관계 | 매장·업무·신입·선배·고정/그날 + 확인 기록의 `confirmed_by` + 맡기기 위임 플래그 | 자격은 저장하지 않고 "맡았어요"에서 계산 | 새 표 1·열 1·플래그 1 | D |
| 데이터 | 내 공간 | `units.kind='personal'` | 계정 층 판정(`isOwnerAccount`)에서 제외 | 새 kind | H |
| 확인 경로 | 알기 → 퀴즈 | 기존 17종 + "사진에서 찾기" | 묶음은 5개씩, 재확인 간격은 유형별(수치 짧게·이름 길게) | 있음 + 형식 1종 | A·C |
| 확인 경로 | 하기 → 수행 기록 | 할일 완료 + '혼자 했어요' 1탭. 퀴즈 없음 | 그 업무 할일을 노하우 보면서 1회 완료하면 "혼자 했어요". 체크리스트는 할일 상세에 노하우 순서 그대로 | 할일·자청 재사용 | B |
| 확인 경로 | 겪기 → 사장 확인 | 사장 화면 사람 상세에 "맡겨도 돼요" 1탭. 상황 문항은 보조 | "혼자 했어요" 상태인 직원·업무만 후보. 사장이 고르지 않아도 되게 후보는 코드가 추린다 | 1탭 추가 | B·D |
| 확인 경로 | 선배 확인 | 사수 할일 카드의 체크 3개(보여줬어요·같이 했어요·시켜봤어요) | 선배는 1~3칸, 사장은 4칸. 위임 플래그로 4칸도 가능. 안전·법규는 위임 불가 | 새 할일 종류 | D |
| 코스 | 프리셋 = 묶음 조합 | 첫 출근 = 알기(금지)+하기 루틴 · 혼자 맡기기 전 = 하기 · 이럴 땐 어떻게 = 겪기 · 잊지 않게 = 알기 재확인 · 자리 바뀔 때 | 프리셋이 묶음을 정하면 담을 노하우 후보를 꼬리표로 거른다 | 프리셋 이름·필터 | E·B |
| 코스 | 첫 출근 자동 생성 | 노하우 4개(4문답) 차면 코스·문항·게스트 링크를 코드가 만든다 | 자동 생성은 첫 출근 코스 하나에만. 사장 직접 풀기가 검수 | 새 연결 | F |
| 직원 화면 | 코스 카드 · 할일 · 허브 성장 | "다음 한 개"는 그대로. 진행 문구만 네 상태 단어로 | 알기 카드는 퀴즈로, 하기 카드는 할일로 연다. 같은 카드, 다른 문 | 문구·분기 | B |
| 직원 화면 | 홈 | 합류 3일 첫 출근 카드, 이후 "오늘 한 줄" | 근무표 × 다음 한 개에서 생성 | 카드 1종 | F·E |
| 사장 화면 | 퀴즈 탭 히어로 · 사람 상세 | "혼자 맡길 수 있는 업무 n/m" · 사람 상세 상단은 네 상태별 업무 묶음 | 점수 없음. 상태만. 파지율·재질문률은 콘솔에서 먼저 | 숫자 교체 | B |
| 사장 화면 | 홈 | "이번 주 아낀 사장님 시간", "오늘 민수에게: …" 한 줄, 경고행 2줄 | 대신 답한 건수 × 3분 + 혼자 한 일 | 집계 + 문구 | F·B |
| 사장 화면 | 대화 (코치 채팅) | 첫 출근 4문답 스크립트, 대화 안 블록 3종(미리보기·문항·결과 한 줄), 결과·합류 턴 | 코치 채팅 파이프·음성·턴 렌더러 재사용 | 스크립트 1 + 블록 3 | F |
| 선배 화면 | 홈 · 할일 · 정산 · 성장 | "내 일이 줄었어요" 한 줄, 사수 할일, 정산 "교육" 한 줄, "내가 알려준 것" 카드 | 자기에게 온 신입·업무만 | 각 1종 | D |
| 측정 | 묶음별 성공 지표 | 알기: 재확인 첫 시도 정답률 · 하기: 통과→실제 수행 전환율, 루틴 완료율 · 겪기: 사장 확인까지 걸린 일수, 통과 후 재질문률 | `quiz_attempt_items` · `task_understanding` · `chat_queries` 조합. 새 테이블 없음 | SQL 집계 | G |
| 측정 | 활성화 | 첫 세션 완주율 · 첫 결과 도달 시간 · 7일 합류율 | `app_events` · `quiz_links` · 합류 기록 | SQL 집계 | F·G |
| 측정 | 두 허들 공통 집계 | 사람별·주별 "노하우가 대신 답한 건수" · "혼자 한 일 건수" | 사장의 "아낀 시간"과 선배의 "줄어든 질문"의 공통 원천 | SQL 집계 1개 | F·D |

## 3. 지금 서비스와의 간극 (우선순위 순)

| 우선 | 간극 | 지금 | 필요한 것 | 종류 |
| --- | --- | --- | --- | --- |
| 0 | 묶음 지식을 담을 그릇이 없다 | 기물 20종의 자리가 노하우 구조에 들어가지 않고 문항 3개로 확인되지 않는다 | "자리 지도" 노하우 유형과 "사진에서 찾기" 확인 형식 | 데이터 유형 |
| 1 | 퀴즈 통과가 교육의 끝으로 읽힌다 | 사장 화면은 이수·정답률이 최종 숫자 | 파지·행동 지표를 콘솔에 먼저 쌓고, 사장 화면은 "혼자 할 수 있는 직원" 중심으로 | 기획 |
| 2 | "해 봐야 되는 지식"을 퀴즈만으로 확인한다 | 순서·기기 조작도 문항 통과만으로 통과 | 알기·하기·겪기 꼬리표와 "실제 수행 1회" 조건 | 기획 |

| 4 | 재확인 간격이 지식 유형과 무관하다 | 모든 노하우가 3·14·56·180일 | 유형별 기본 간격. `schedule.ts` 상수 하나로 가능 | 기술 |
| 5 | 3단계(판단)에 맞는 코스가 없다 | 프리셋은 첫 출근·주말·정기·포지션 | "이럴 땐 어떻게" 코스: t5 갈래 문항만, 2주 이후 자동 제안 | 기획 |
| 6 | 암묵지(태도·감각)를 확인할 자리가 없다 | 퀴즈 밖의 것은 기능이 없다 | 사장 관찰 체크 한 개(노하우당 1탭) | 기획 |
| 7 | 이탈 단계에 교육 기능이 없다 | 아무도 모르는 노하우는 "통과자 0"만 | "한 사람만 아는 노하우" 경고, 퇴사자가 남기는 요령 수집 | 기획 |
| 8 | 사장에게 "언제 무엇을" 안내하는 가이드가 없다 | 프리셋 설명 한 줄 | 첫 출근 4문답 (04) | 기획 + 콘텐츠 |
| 9 | 교육 용어가 코드·화면·기획에서 같지 않다 | 코스·퀴즈·훈련·이해 확인이 섞여 쓰임 | 05의 어휘 두 벌을 정본으로, 화법 가이드와 맞춤 | 내부 프로세스 |

## 4. 바꾸지 않는 것

- 퀴즈 만들기 5단계. 자동 생성은 첫 출근 코스 하나에만.
- 검수 없이 문항이 나가지 않는다. 사장이 미리보기에서 직접 풀어본 것이 검수.
- 줄세우기 금지(D1~D5). 사람 옆에는 상태만, 핀 단위·문항 단위 개인 점수 없음.
- 실패 미저장 원칙의 화면 측면. 틀린 것은 직원 본인과 문항 오답률에만.
- 매니저 역할. 사수는 매니저와 독립인 업무 단위 확인 권한.
- 직원·급여 화면에 교육 상태를 넣지 않는다.
