# 09. 개인 공간과 일 이력

분기 H. 실행 순서 5번. 사장이 매장을 만들어야만 시작되는 구조를 바꾼다. 알바·선배도 자기 공간을 갖고 인수인계를 쓰며, 그 기록이 일 이력으로 이어진다. D(담당자 구조)와 허들 2-D(경력 카드)의 바닥이고, 알바에서 사장으로 가는 유입 경로다.

## 1. 문제

지금은 사장이 매장(`units`)을 만들어야 모든 것이 시작된다. 알바는 초대코드로 합류하는 사람이고, 사장이 가입하지 않은 매장의 알바는 서비스에 설 자리가 없다. 그런데 인수인계를 가장 절실하게 느끼는 사람은 떠나는 알바와 받는 후임이다. 사장은 그 사이에 없는 경우가 많다.

## 2. 공간 계층을 하나 더 둔다

계정 아래에 공간이 세 층이 된다. **내 공간(개인) → 매장(공유) → 브랜드(본사).** 지금은 가운데와 오른쪽만 있다. 내 공간은 가입하면 누구에게나 생기고(만들기 없음), 여기 쓴 것은 전부 본인 것이다. 노하우 구조·코치 채팅·사진·음성·AI 질문이 그대로 동작한다. 다른 것은 "누가 읽나"뿐이다.

| 공간 | 누가 만드나 | 쓰는 사람 | 읽는 사람 | 기존 |
| --- | --- | --- | --- | --- |
| 내 공간 | 가입 시 자동 | 본인 | 본인 + 본인이 링크로 초대한 사람 | 없음 |
| 매장 | 사장 (또는 내 공간에서 승격) | 사장·매니저·제안하는 직원 | 합류한 전원 | 있음 |
| 브랜드 | 본사 | 본사 | 가맹 매장 | 있음 |

## 3. 내 공간이 하는 일 세 가지

**1. 사장 없는 인수인계.** 떠나는 알바가 내 공간에 매장 이름만 적고 요령을 남긴다(코치 채팅이 "다음 사람이 첫날 제일 많이 헤맬 걸 말해 주세요"로 묻는다). 후임에게 링크로 넘긴다. 후임은 로그인 없이 읽고 묻는다(게스트 링크 확장). 사장이 나중에 가입하면 "이 매장 요령이 이미 14개 있어요. 가져올까요?"가 뜨고, 쓴 사람의 동의로 매장에 복사된다. **알바가 만든 공간이 매장의 씨앗**이 된다. 사장 영업의 두 번째 경로다.

**2. 매장 안에서의 내 메모.** 매장이 있어도 알바는 자기 요령을 내 공간에 먼저 쓴다(매장 노하우와 분리). "매장에 올리기"를 누르면 기존 제안 흐름으로 간다. 선배가 맡은 업무라면 08의 2-C대로 사후 승인으로 바로 나간다. 내 공간은 매장을 옮겨도 남는다.

**3. 일 이력.** 내 공간의 기록과 매장에서 쌓인 상태(혼자 맡은 업무, 알려준 사람, 교육 시간)가 한 장의 **일 이력 카드**가 된다. 항목은 업무 단위다. "에스프레소 머신 혼자 운용 · ○○카페 · 2026.3~9 · 사장 확인". 사장 확인(맡겼다 상태)이 있는 항목만 "확인됨" 배지가 붙고, 나머지는 본인 주장으로 표시된다. 공유는 본인만 한다. 요식업 알바에게 없던 **기술 증명**이고, 허들 2-D가 말한 장기 동기의 실체다.

## 4. 왜 두 허들에 붙는가

- 선배의 가치(허들 2)가 매장 밖으로 이어진다. 가르친 기록이 매장을 그만두면 사라지는 것이 아니라 본인을 따라간다.
- 사장이 없는 매장에서도 서비스가 시작된다. 알바가 쓴 14개가 사장의 첫 입력 비용을 0으로 만든다(04의 1-C의 또 다른 입구).
- 사장이 매장을 "만드는" 결정을 하지 않아도 된다. 이미 있는 것을 "받는" 결정만 한다. "예"가 아니라 "가져오기" 한 번이다.

## 5. 구현 형태와 주의점

| 항목 | 형태 | 주의 |
| --- | --- | --- |
| 내 공간 데이터 | `units` 행에 `kind='personal'`. 노하우·퀴즈·질문이 그대로 동작 | personal을 소유한다고 사장 계정(`isOwnerAccount`)이 되면 안 된다. 계정 층 판정에서 personal 제외 |
| 인수인계 링크 | 게스트 퀴즈 링크(0113) 패턴을 읽기·질문으로 확장 | 로그인 없는 경로는 definer RPC + 토큰만. RLS를 열지 않는다 |
| 매장으로 가져오기 | 다점포 복사(`import-knowhow`)와 같은 복사. 원본은 내 공간에 남음 | 쓴 사람의 동의 필수. 사장이 일방적으로 가져가지 못한다 |
| 일 이력 카드 | `my_training_history` + 상태 사다리 + 사수 기록을 이미지·링크로 | 사장 확인 없는 항목은 "본인 주장"으로 표기. 점수·등급 없음. 개인정보 지침 항목 추가 |
| 매장 이름 충돌 | 같은 매장을 알바 둘이 각자 내 공간에 적을 수 있다 | 사장이 매장을 만들 때 둘 다 "가져오기" 후보로. 자동 병합 안 함 |

## 6. 관계

- 05의 사다리 4칸(맡겼다)이 일 이력의 "확인됨" 배지다.
- 08의 J(가르친 기록)와 2-D(경력 카드)의 저장소가 이 공간이다.
- 04의 입력 비용 0 경로 중 하나다.
- 분기 순서에서는 D 앞에 놓는다.
