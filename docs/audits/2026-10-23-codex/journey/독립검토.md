# JOURNEY-01 수정 독립 검토

판정: **요청 범위에서 고쳐야 할 항목 0개.** 알림을 눌러 앱을 연 뒤 연결 복구와 재로그인을 거쳐도 목적지를 보관한다. 명시적 로그아웃과 계정 변경에서는 이전 목적지를 폐기한다.

제품 `src/lib/push/nativepush.ts`의 diff, 전체 처리 흐름, `clearDeviceNotifications` 호출부, 새 재현 스크립트를 읽었다. 제품 코드를 변경하지 않았다. 수정 전 사본과 현재 모듈을 각각 독립 실행했다.

## 반박 검토

- 실제 nativepush 모듈과 실제 경로 판정 모듈을 실행한다. 네이티브 알림 API, 세션, 라우터, 매장 진입은 모의했다. Supabase 사용은 테스트에서 오류를 내도록 막았다.
- 일시적인 signed_out에서는 구독을 해제하지 않는다. 이후 signed_in에서 목적지를 처리한다. 이 변경이 기존 결함의 원인과 직접 연결된다.
- 명시적 로그아웃은 `tapBlocked`와 세대로 처리 중인 알림을 취소한다. 지연된 초기 OS 조회와 구형 알림 메타데이터 응답도 새 계정에서 라우팅하지 않는다.
- 계정 변경 전후의 async import에도 현재 세대와 userId를 확인한다. 다른 매장 알림은 라우터로 바로 가지 않고 기존 매장 진입 절차를 따른다.
- 리스너로 더 최근에 누른 알림이 들어오면 초기 OS 조회의 늦은 응답이 덮지 않는다. 같은 알림의 콜드 응답과 리스너 중복도 막는다.
- 알림 없음, 정상 콜드 시작, 로그인 후 새 알림, 외부 URL 거부를 대조군으로 확인했다.

## 범위 제한

실제 기기의 OS 콜드 스타트, Expo 알림 전달, 실제 세션 복구, 매장 전환 전체 여정은 미실행이다. 테스트의 Android/iOS 문자열 분기 통과를 두 플랫폼 실제 동작 통과로 보고하면 안 된다. `useStoreEntryStore.enter` 내부의 권한과 계정 변경 처리를 이 검사로 새로 보증하지 않는다.

실기기에서는 알림으로 앱 열기 → 초기 연결 실패 → 같은 계정 복구 → 해당 업무로 이동을 확인해야 한다. 명시적 로그아웃 뒤 다른 계정 로그인에서는 이전 알림이 열리지 않아야 한다. 기존 계정의 늦은 응답을 취소한 뒤 새 알림을 눌렀을 때 정상 이동도 확인해야 한다.
