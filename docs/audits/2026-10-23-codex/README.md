# Codex 추가 감사와 수정 기록

2026-10-23. 사용자가 추가 감사 뒤 결함 1~4 수정을 승인했고, 검증 기록을 포함한 로컬 커밋을 요청했다. push, 배포, 운영 DB 변경, 운영 계정 생성, 실제 결제나 발송은 수행하지 않았다.

## 변경 범위

| 결함 | 수정 내용 | 제품 변경이 포함된 위치 |
|---|---|---|
| AUTH-LIFE-01 | 탈퇴 계정의 REST/RPC와 RLS 접근 차단. Auth ban과 해당 계정 세션 제거. 기존 탈퇴 계정 보정. 열린 소유 매장에 직원이 남으면 탈퇴 거부. 직원 승인과 탈퇴의 경쟁 방어 | 이번 커밋의 `supabase/migrations/0335_deleted_account_access.sql` |
| STOR-01 | 오래된 근태 저장 실패가 최신 성공 상태를 덮지 않음. 삭제 실패의 중복 복원 방지. 실패 행 재조회도 이후 변경과 계정 전환을 존중 | `448afcb502da9b38f84926b151d06fd804ed579a`에 다른 작업자가 함께 커밋 |
| JOURNEY-01 | 앱을 알림으로 열었을 때 일시적 인증 실패 후 복구해도 목적지를 유지. 로그아웃과 계정 변경 시 이전 알림 폐기 | `d59735f`에 다른 작업자가 함께 커밋 |
| OBS-01 | 오류와 이용 기록의 공유 퀴즈 URL에서 토큰 제거 | `d59735f`에 다른 작업자가 함께 커밋 |

앞선 세 파일을 다시 수정하거나 중복 커밋하지 않았다. 위 두 기존 커밋에는 타 작업자의 다른 수정도 있으므로 전체 커밋을 Codex 작업이라고 분류하지 않는다. 해당 제품 파일은 각각 `src/lib/store/useAttendanceStore.ts`, `src/lib/push/nativepush.ts`, `src/lib/analytics/track.ts`다.

## 증거 읽는 방법

- `auth/`: 격리된 전체 스키마 DB와 실제 PostgREST HTTP 검증, 승인 경쟁 재현, 독립 보안 검토.
- `storage/`: 실제 상태 모듈과 모의 응답 순서. 현재 코드 14개 시나리오 통과.
- `journey/`: 실제 알림 모듈과 플랫폼 모의. Android/iOS 각 17개, 총 34개 통과.
- `observability/`: 7개 경로에서 오류/이벤트 두 기록의 토큰 제거를 확인. 14개 계약 통과.

최종 서버 검증은 기본 26개 단언(실제 HTTP 18건과 SQL 상태 검사), 승인 경쟁 2개, 직접 RLS 5개가 모두 통과했다. 별도 새 DB의 전체 마이그레이션 적용도 확인했다. 독립 검토의 커밋 차단 항목은 0개다. 감사용 두 DB와 임시 REST 컨테이너는 검사 뒤 정리했다.

기록을 저장소에 넣은 뒤 `npm run typecheck`, `npm run lint`가 모두 종료 코드 0으로 끝났다. 린트에는 기존 `billing.tsx`, `analytics/posthog.ts` 경고 2개가 남는다. 재현용 과거 소스는 `.ts.txt`로 보관하여 앱 타입 검사와 번들 대상에 섞이지 않게 했다.

RED는 결함이 존재했던 기준 파일의 실패 증거다. 이를 제품 검사 통과로 세지 않는다. GREEN과 current-results는 해당 실행 시각 및 해시에만 유효하다. 원래 상세 산출물은 저장소 바깥 `산출물/추가품질감사_2026-10-23`에 보존했다. 이 폴더에는 재현에 필요한 파일과 선별 증거만 포함한다. 운영 키, JWT, 실제 개인정보와 DB 전체 덤프는 포함하지 않는다.

## 적용 전 확인과 남은 한계

0335는 로컬 파일로 작성하고 격리 DB에서 검증했다. 운영에는 적용하지 않았다. 적용 담당자는 PostgREST의 DB 설정 사용 여부와 환경 변수의 기존 pre-request/pre-config 충돌을 확인해야 한다. 별도 hook이 있으면 이 검사를 보존해서 통합해야 한다. 새 public RLS 테이블은 같은 제한 정책을 추가해야 한다.

실제 Auth 서버의 로그인 HTTP, Storage 서비스 HTTP, Realtime 재연결, 실기기 화면 검사는 수행하지 않았다. Auth ban 동작은 GoTrue v2.197.0 공식 소스를 검토했고 DB 상태 변경을 확인했다. 이미 발급된 파일 서명 URL, 이미 인증을 통과한 진행 중 Edge 요청, 기기에 내려받은 자료를 소급 회수하는 변경은 아니다. 구형 앱에서는 탈퇴 계정 재로그인 시 비밀번호 확인 문구가 나올 수 있다.

Android/iOS에서 확인할 화면과 행동:

1. 설정의 회원 탈퇴: 직원이 있는 사장은 직원 관리 안내를 받는다. 직원이 없는 사장은 탈퇴할 수 있다.
2. 근태 수정: 연속 저장 중 먼저 보낸 요청만 실패해도 나중에 저장한 값이 유지된다.
3. 업무 알림: 앱 시작 중 연결 실패 뒤 같은 계정으로 복구하면 원래 업무가 한 번 열린다. 다른 계정으로 바꾸면 이전 알림을 열지 않는다.

이 기록은 실제 기기와 운영 환경의 전체 QA 통과 선언이 아니다.
