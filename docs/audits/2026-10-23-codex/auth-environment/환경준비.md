# AUTH-LIFE-01 격리 전체스키마 검증 환경

## 생성한 것

- 별도 DB: `audit_auth_full_1792737494969`.
- 별도 REST 컨테이너: `audit_auth_rest_1792737551371`.
- 원본 로컬 DB: `supabase_db_SquareTable`의 `postgres`. schema-only dump만 읽었다.
- 복원한 public 테이블 92개, 전체 RLS 정책 149개, 사용자 트리거 63개. 최초 auth.users는 0행이다.
- 원본 테이블 데이터, 사용자, 세션, 저장 파일, Vault secret, cron job은 복사하지 않았다.
- 새 JWT 서명키는 이 환경에서 임의 생성했다. 운영 서명키를 사용하지 않는다. 키는 별도 REST 컨테이너 설정에만 있다. 로그와 파일에 키나 JWT를 쓰지 않는다.

## 기준과 차이

원본 migration ledger는 0330까지만 기록돼 있다. 하지만 0334의 함수도 실제 DB에 존재했다. ledger와 실제 함수는 다르므로 ledger만으로 원본을 0330 계약이라고 단정하면 안 된다.

schema-only dump를 별도 DB에 복원하고 저장소의 0331, 0332, 0333, 0334를 그 DB에만 적용했다. 이 네 파일에서 전역 ALTER ROLE, cron.schedule, net.http 호출은 발견되지 않았다.

적용 후 함수 386개를 원본과 해시 비교했다. 차이는 4개다. 0331의 초대 수락/취소/응답 함수 3개와 0332의 my_units_notif_data다. 상세는 `function-drift.json`에 있다. 원본과 격리 DB의 AUTH-LIFE-01 핵심 인가 함수는 이 과정에서 변하지 않았다.

`environment.json`은 DB 이름, 컨테이너 이름, 적용 파일 해시, source ledger와 핵심 함수 해시를 기록한다. `schema-only.sql`은 실제 전체스키마 원본이다. `restore.log`와 각 migration log는 복원 근거다.

## 호출 방법

`client.cjs`의 `sql(source)`는 이 감사 DB에만 SQL을 실행한다. `request({method,resource,claims,body})`는 실제 PostgREST HTTP를 실행한다. claims에 합성 sub와 필요하면 session_id를 전달한다. role 기본값은 authenticated다. 반환값은 `{status,data}`다.

HTTP는 DB 컨테이너 네트워크 공간의 `127.0.0.1:13023`에서만 열린다. 호스트나 외부로 포트를 공개하지 않았다. helper가 DB 컨테이너 내부 curl을 사용하므로 부모도 이 helper로 접근하면 된다.

빈 DB에서 합성 사용자 claim으로 `/rpc/auth_unit_id`를 호출해 HTTP 200과 null을 확인했다. 이는 합성 JWT 서명 검증을 통과한 대조일 뿐, 탈퇴 권한 수정 통과 증거는 아니다. 전체 fixture와 수정 전후 판정은 부모 담당이다.

## 외부 실행 경계

로컬 pg_net worker의 database_name은 원본 postgres로 고정돼 있다. 별도 audit DB의 큐는 이 worker의 대상이 아니다. 원본 확장에 http, dblink, pg_cron은 설치돼 있지 않다. 사용자 트리거 함수 본문에서 직접 net/http/cron 호출은 0개였다. schema-only 복원이라 cron job이나 외부 발송 대기 행도 복사되지 않았다. 실제 알림 서비스 컨테이너나 Auth 서비스를 새 환경에 연결하지 않았다.

모든 트리거와 RLS는 원본대로 유지했다. 발송을 막기 위해 가짜 인가 함수나 트리거 no-op을 넣지 않았다. 이후 fixture가 추가되면 트리거가 만든 알림 행은 이 DB에만 존재한다.

## 정리

부모의 HTTP/SQL 검증이 끝나면 `node .../auth-environment/cleanup.cjs`를 실행한다. 이 스크립트는 manifest에 기록한 audit 접두사의 DB와 REST 컨테이너만 제거한다. 기존 개발 DB, 기존 컨테이너, 저장소 파일을 지우지 않는다. 실행 시각은 manifest의 cleanedAt에 남는다.

현재는 부모의 후속 검사를 위해 환경을 유지한다. 제품 코드, 공유 DB의 데이터나 스키마, 운영 설정은 변경하지 않았다.
