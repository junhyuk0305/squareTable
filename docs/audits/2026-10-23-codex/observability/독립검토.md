# OBS-01 수정 독립 검토

판정: **요청 범위에서 고쳐야 할 항목 0개.** 공유 퀴즈 경로의 접근 토큰을 `client_errors.route`와 `app_events.route`에 기록하지 않는 수정이 확인됐다.

검토자는 제품 파일을 수정하지 않았다. `src/lib/analytics/track.ts`의 diff와 전체 호출 경로, 재현 스크립트를 읽었다. 동일한 스크립트를 수정 전 사본과 현재 소스에 각각 독립 실행했다. 실제 네트워크와 운영 DB를 사용하지 않았다.

## 실행 근거

| 대상 | 관찰 | 종료 코드 | 소스 SHA-256 |
|---|---|---|---|
| `fixes/observability/before-track.ts` | 공유 토큰, URL 인코딩 토큰, 끝 슬래시의 3사례 실패. 정상 대조 4사례 통과 | 1 | `b492602f66a1246a10d72e22f63547cc877409c6c5600b088bd2b1c20514a8b0` |
| 현재 `src/lib/analytics/track.ts` | 같은 7사례 모두 통과 | 0 | `ea449897460b3764efac72e5f50f36d4d006039d18d1daa8736167bca7970fea` |

현재 실행 시각은 `2026-10-23T06:24:54.700Z`다. 수정 전 실행 시각은 `2026-10-23T06:24:54.722Z`다. 두 실행은 서로 다른 VM 상태이며 독립 병렬 실행했다. 각 실행은 실제 TypeScript 모듈을 변환해 실행하고 통신 모듈만 모의했다.

검사 명령은 `node fixes/observability/test-route-token.cjs <수정 전 파일>`과 같은 명령의 파일 인자 생략형이다. 실제 파일은 이 감사 폴더 아래에 있다.

## 반박 검토

- 문자열 변환만 따로 복제해 통과한 검사가 아니다. 실제 `reportError`와 `track`을 호출해 각각의 INSERT 대상을 관찰한다.
- `^/q/[^/]+`는 첫 토큰 구간을 통째로 `[token]`으로 바꾼다. `%2F`처럼 인코딩된 문자가 있는 경우도 토큰 전체를 지운다.
- 일반 `/owner/work`와 비슷한 `/owner/quiz/ordinary-id` 경로는 그대로 남는다. 원래 쓰던 화면 식별 기능을 손상하지 않았다.
- query와 hash를 수집하지 않던 기존 pathname 계약은 유지된다. 네이티브처럼 window가 없으면 null이다.
- 모의 INSERT 거절도 다시 예외로 전파되지 않았다. 계측 실패가 화면 동작을 깨지 않는 기존 성질이 유지된다.
- 테스트는 한 사례마다 새 모듈 상태를 사용하므로 기존 중복 억제에 의해 검사가 누락되지 않는다. 각 사례에서 두 행을 확인한다.

## 범위 제한

이 수정은 route 컬럼만 다룬다. 오류 message, meta, 이벤트 props에 사용자가 직접 넣은 비밀값과 PostHog 자동 수집까지 정리한 수정은 아니다. 수정 전 남은 로그의 삭제도 수행하지 않았다. 그러한 범위까지 해결했다고 보고하면 안 된다.

실제 브라우저와 두 모바일 플랫폼의 종단 검사는 수행하지 않았다. 이번 변경은 공통 순수 경로 변환이므로 실행된 모듈 수준 검사는 변경 검증에 적절하다. 배포 완료 또는 운영 기록의 제거를 뜻하지 않는다.
