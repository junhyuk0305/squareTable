# STORAGE-01 수정 독립 검토

판정: **요청 범위에서 고쳐야 할 항목 0개.** 이전 근태 저장 요청의 늦은 실패가 최신 저장 상태를 덮는 문제와 삭제 실패의 중복 복원을 막았다.

제품 파일 `src/lib/store/useAttendanceStore.ts`의 diff와 상태 처리, `guardWrite`, 읽기 복구 경로, 재현 스크립트를 읽었다. 제품 파일은 변경하지 않았다. 재현 스크립트를 수정 전 사본과 현재 코드에 각각 독립 실행했다.

## 기준과 실행

최종 제품 SHA-256은 `7548962ddcf9f3c86124994cf08aafa1a971aa7355822deba41262be75ba24c0`이다. 담당자가 추가 경계 검사를 반영하는 중에 검토를 시작했다. 초기 12사례 결과와 최종 14사례 결과를 섞지 않았다.

| 대상 | 최종 14시나리오 결과 | 근거 |
|---|---|---|
| `before.ts` | 실패 단언 5개. productPass=false. Node 종료 코드 1 | `독립검토_STORAGE_red14.json` |
| 현재 제품 | 실패 단언 0개. productPass=true. Node 종료 코드 0 | `독립검토_STORAGE_green.json` |

수정 전 소스 해시는 `359bc5214e11057abb7109a63405c5f7f42ac1d546d1f52a51a8f7f4f35aa8b4`다. 현재 실행 종료 시각은 `2026-10-23T06:29:11.493Z`, 최종 수정 전 실행 종료 시각은 `2026-10-23T06:29:31.277Z`다. 각 실행의 전후 소스 해시 차이는 없었다. 먼저 실행한 `독립검토_STORAGE_red.json`은 12시나리오 구판 검사다. 최종 비교에는 쓰지 않는다.

Node 프로세스의 표준 출력을 PowerShell로 파일에 저장했기 때문에 외부 명령의 종료 코드는 Node 직후 `$LASTEXITCODE`로 별도 확인했다. PowerShell 전체 종료 코드 0을 제품 검사 통과로 해석하지 않았다.

## 반박 검토

- 실제 Zustand 저장소와 실제 guardWrite를 실행한다. DB 왕복만 모의한다. 오류가 생겨야 할 시점과 성공한 서버 행을 명시적으로 제어한다.
- 이전 A 실패, 최신 B 성공 사례에서 로컬과 모의 서버가 모두 660분을 유지한다. 예전 구현은 로컬을 480분으로 되돌린다.
- 실패 롤백이 같은 ID의 모든 행을 바꾸지 않고 해당 쓰기가 남긴 객체만 되돌린다. 재조회나 더 최신 편집이 만든 객체는 보존한다.
- 삭제 실패 시 같은 ID가 재조회로 이미 돌아와 있다면 다시 삽입하지 않는다. 중복 행에 따른 합계 부풀림을 막는다.
- A/B가 모두 실패하는 경우에는 롤백만으로 실패한 A 값이 남을 수 있다. 따라서 같은 기록의 진행 중인 쓰기가 끝난 뒤 실패 기록을 다시 읽는 처리가 필요하다. 순서대로 실패와 역순 실패 모두 480분으로 복구한다.
- 복구 조회는 월 범위로 하되 실패한 ID 하나만 바꾼다. 같은 달의 다른 행을 과거 값으로 덮지 않는다.
- 복구 시작 뒤 C 저장 또는 새로운 실시간 조회가 들어오면 version과 객체 비교로 오래된 복구 결과를 버린다. 세대가 바뀌면 이전 매장 결과도 버린다.
- 복구 읽기가 실패해도 최신 B 성공은 유지한다. 복구 실패를 성공 저장으로 표시하는 코드는 추가하지 않았다.
- 실패 단언을 모으는 검사 스크립트는 하나가 실패해도 다음 사례를 실행하며 마지막에 실패 수와 종료 코드 1을 남긴다. 실패를 분모에서 제외하지 않는다.

## 범위 제한

실제 DB, 다른 기기, 화면, 급여 금액은 실행하지 않았다. 모의 서버에서 업무 시간과 저장 상태를 비교한 증거다. 서버에 도착한 두 성공 요청의 순서 자체를 직렬화하는 수정은 아니다. 기본 hydrate와 다른 화면의 모든 경쟁을 해결한 것으로 확장해서 보고하지 않는다.

현재 저장 API와 DB 스키마를 바꾸지 않는다. 구형 앱은 기존 동작을 유지하며 수정 효과는 새 클라이언트에 적용된다. 실제 Android/iOS에서 동일 기록을 연속 수정하고 앞 요청을 실패시킨 뒤 최신 값이 유지되는지, 삭제 실패 뒤 행이 하나만 보이는지 확인이 남는다.
