# 매장의 정석 UI 작업

1. 저장소 `docs/design-system-v2.md`를 읽는다. 구현 범위는 `docs/design-system-v2-rollout.md`를 확인한다.
2. 기존 화면의 라우트와 실제 위임 컴포넌트를 찾는다. 현재 호출 계약·권한·데이터 범위를 기록한다. 전면 탐색은 저장소 AGENTS.md의 위임 원칙을 따른다.
3. 같은 카테고리는 제목·내용·관련 행동을 한 박스에 둔다. 반복 항목은 내부 행이다. 기존 SectionGroup이 있으면 재사용한다. 아직 없으면 두 사용처와 함께 최소 구현한다.
4. 노랑은 브랜드 요약·시작·진행에 활용한다. 선택/정답/오답/해설은 정본의 역할표를 따른다. 색값을 이 스킬에 복제하지 않는다.
5. 히트맵은 질문 횟수와 직원 이해 비율을 구별한다. 허브는 계정 전체 범위와 현재 매장 범위를 구별한다.
6. 실제 반영 전에 정상·빈 상태·로딩·실패·긴 내용 시안을 보여준다. 구현 전 시안과 실제 서비스 화면을 명확히 구분한다.
7. 구현 후 의미 그룹 검사와 실제 렌더를 확인한다. 0개 마커나 실행하지 못한 화면을 통과로 세지 않는다.
8. Android/iOS는 HTML 모양으로 검증했다고 하지 않는다. 키보드·safe area·뒤로가기·글자 확대·스크린리더의 실제 확인 목록을 넘긴다.

정보 위계(2026-10-28 사용자): 박스마다 읽혀야 할 순서를 화살표 한 줄로 먼저 적는다. 그 줄에 든 말만 크게·굵게 하고 나머지는 작은 보조색으로 내린다. 핵심과 맥락이 한 문장에 섞이면 줄을 나눈다. 단계가 바뀌면 크기·굵기·색·바탕 중 둘 이상을 바꾼다. 크기·굵기 값은 토큰에서 고른다. 큰 글씨만 이어 읽어서 그 줄이 나오면 통과다. 상세는 전역 `uiux-blocks` §6 "정보 위계"를 본다.

전역 uiux-blocks의 카드 1~2개, 동일형태 3연속 금지, 2열 강제는 이 프로젝트에 적용하지 않는다. 참고 앱을 다시 조사할 때는 해당 스킬의 출처 확인 절차만 이용한다. 다른 프로젝트의 전역 스킬 파일을 이 앱 취향으로 바꾸지 않는다.

완료 보고: 바꾼 공통 부품, 화면별 이관 상태, 검증 결과, 미검증 플랫폼. UI 변경과 서버 기능 변경을 같은 완료 문장으로 합치지 않는다.
