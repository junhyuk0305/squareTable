# Play 출고 게이트 — 조항별 확인표

`scan-play.mjs` 가 자동으로 보는 것과, 사람만 볼 수 있는 것의 경계를 적는다.
**정본 문서는 `출시서류_안드로이드/` 다.** 여기에 그 내용을 복제하지 않는다 — 이 문서는
**코드·설정과 그 문서가 어긋났는지**만 다룬다.

---

## 1. 서명 — 되돌릴 수 없는 유일한 항목

Play 는 **최초 업로드에 쓴 업로드 키**로만 이후 업데이트를 받는다. 키를 잃으면 구글에 재설정을
요청해야 하고, 그 사이 업데이트가 막힌다.

| 확인 | 지금 상태 | 규칙 |
|---|---|---|
| `eas.json` → `production.android.credentialsSource` | `"local"` | ⛔EAS 관리 키로 바꾸지 않는다 |
| `credentials.json` → `keystorePath` | `../_로컬전용/android-signing/android.keystore` | 저장소 **밖**에 둔다 |
| `credentials.json` 자체 | `.gitignore:91` | 평문 비밀번호가 들어 있다 — 절대 커밋하지 않는다 |
| 키스토어 백업 | `_로컬전용/android-signing/` | 이 PC 가 죽으면 같이 죽는다. 백업 위치를 사용자가 안다 |

메모리: `project_squaretable_android_upload_key_2026-09-03`

## 2. 권한 — 정본은 세 곳이고 아래로 갈수록 강하다

1. `app.json` — 우리가 쓴 것 (거의 비어 있다: `android.permissions` 없음)
2. `expo config --type introspect` — 플러그인 포함. **★빌드 타입을 모른 채 디버그 소스셋까지 합친다**
3. **Play 콘솔 → 앱 번들 탐색기 → 권한** — 업로드된 aab 의 진실 (**정본**)

`scan-play.mjs --introspect` 는 2번을 뽑아 `출시서류_안드로이드/12_Play_추가선언_권한문구_*.md` §2 의
신고표와 대조한다. **아무것도 걸러내지 않는다** — 2번에 남아 있는 것은 전부 앱이 직접 선언하는
권한이고 릴리스에 그대로 들어간다.

**차이가 나면 방향을 구분한다:**
- **2번에만 있다** → 앱이 선언하는데 신고 안 한 것. 쓰지 않는 권한이면 `android.blockedPermissions` 로 제거한다.
- **신고표에만 있다** → 라이브러리 매니페스트에서 병합되는 것이라 2번에 안 보일 뿐이다
  (예: `POST_NOTIFICATIONS`·`RECEIVE_BOOT_COMPLETED`). 정상이다.

### 실측 이력

| 날짜 | 무엇 | 결말 |
|---|---|---|
| 2026-09-03 | `CAMERA` 가 vc4 에 들어감(쓰지 않는 기능) | `cameraPermission:false` 로 제거 — 지금은 `tools:node="remove"` 확인됨 ✅ |
| 2026-09-11 | `FOREGROUND_SERVICE*` 가 `expo-audio` 기본값으로 들어감 | `enableBackgroundPlayback:false` 추가. **같은 기본값이 iOS 에서 2.5.4 거절을 냈다** |
| 2026-09-18 | introspect 에 `SYSTEM_ALERT_WINDOW` — 신고표에 없다 | 출처 = **Expo 베어 템플릿 매니페스트**(`@expo/config-plugins` 의 "OPTIONAL PERMISSIONS" 블록). `src/main` 이라 **릴리스에 들어간다.** → `app.json` 에 `blockedPermissions` 로 제거 ✅ |
| 2026-09-18 | ↑ 를 한 번 "디버그 전용이라 안 나간다"고 오판 | 같은 이름이 RN 디버그 매니페스트에**도** 있어서 거기서 멈췄다. 그 판단으로 스캐너에 **진짜 권한을 가리는 필터**를 넣었다가 걷어냄. → **출처는 하나 찾고 멈추지 않는다 · 게이트는 시끄러운 쪽으로 틀린다** |

> **교훈(iOS 와 공유): 우리가 선언한 적 없는 것이 선언된다.** 플러그인 기본값은 `app.json` 을
> 읽어서는 영원히 안 보인다 — 최종 산출물을 뽑아야 보인다.

## 3. 정책 게이트

| 게이트 | 자동 확인 | 사람이 볼 것 |
|---|---|---|
| target API 36 | Expo 56/RN 0.85 → 충족 | 콘솔 대시보드에 target API 경고가 없는가 |
| 16KB 페이지 크기 | RN ≥ 0.77 확인 + 네이티브 서드파티 목록 | 업로드 거부 메시지가 지목하는 `.so` |
| versionCode | `appVersionSource: remote` + `autoIncrement` | — |
| 데이터 안전 양식 | 권한 목록 대조까지 | 수집 항목·전송·백업 답안 (`출시서류_안드로이드/03`) |
| 결제 정책 | `npm run native:gate` §3 이 이미 본다 | ⛔여기서 중복 검사하지 않는다 |
| 콘텐츠 등급·타겟층 | — | `출시서류_안드로이드/06`·`11` |

## 4. 코드로는 절대 볼 수 없는 것 (🔑)

| 확인할 것 | 어디서 | 틀렸을 때 |
|---|---|---|
| **FCM V1 서비스 계정 키** | `eas credentials -p android` | 토큰 발급·DB 저장 전부 성공하는데 **알림만 한 건도 안 온다** |
| 업로드 키 종류 | `eas credentials -p android` | 업로드 거부 |
| 실제 aab 권한 | Play 콘솔 → 앱 번들 탐색기 → 권한 | 신고 내용과 달라 심사 질의 |
| 트랙 상태 | Play 콘솔 → 릴리스 | — |

FCM 키 구조는 iOS 의 APNs 와 같다 — **배달 경로 중간에 구글이 끼어 있고, 그 접수증이 없으면
전 구간이 초록불인데 도착만 안 한다.** 코드 어디에도 단서가 남지 않는다.

## 5. 안드로이드에는 롤백이 있다 (iOS 와 다른 점)

잘못 올려도 **이전 릴리스로 되돌릴 수 있고**, 단계적 출시(rollout %)로 피해를 좁힐 수 있다.
그래서 게이트를 iOS 만큼 무겁게 잡지 않는다. 대신:

> **단계적 출시를 쓴다.** 내부 테스트 → 비공개 → 프로덕션 20% → 100%.
> 롤백이 있다는 것은 "막 올려도 된다"가 아니라 **"관측할 시간을 벌 수 있다"**는 뜻이다.
> 되돌릴 수 없는 것은 딱 하나, **업로드 키**다(§1).
